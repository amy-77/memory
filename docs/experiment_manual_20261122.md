## 0. 所有 LaCT 实验共用的设定

### 0.1 模型

- 冻结的 Qwen3-0.6B。注意力只能看每个 token 之前最近的 2048 个 token,外加整段序列开头的 4 个 token。
- 28 层每层挂一个 LaCT 记忆分支(一个小的 SwiGLU 网络,它的权重就是记忆)。
- 记忆分支在 1 万段 16 轮合成对话上训练过(loss 只算在答案上)。
- 权重:h20-1 `/data/qyl/sw_20261122/ckpt/dlg16_new/final/`(下午重训的那份;今天下午之前的结果用的是 9-5 上的原版,同样设置)。

### 0.2 数据(合成,不是真实对话)

- 一段对话 = 若干"轮"。每轮约 259 个 token:标题 `[Turn i]` + 重复的填充文字("The grass is green. The sky is blue. ……")。
- 8 条事实分散在其中 8 轮里,每条一句话,约 18 个 token,例如 `The budget for order N-942 is 64520 dollars.`。约三成事实在后面某一轮被更正成新值。
- 对话之后提问,例如 `Question: What is the budget for order N-942?\nAnswer:`。
- 轮与轮之间除了"更正"之外没有任何关系。
- 测试集:h20-1 `/data/qyl/sw_20261122/data/rc_t16_f8.jsonl`、`rc_t32_f8.jsonl`、`rc_t64_f8.jsonl`(16 / 32 / 64 轮,每份 100 段,随机种子 7)。
- 开发集(只用来定门槛,E10):`/data/qyl/sw_protect_20261122/data_dev/dev_t32_f8.jsonl`(随机种子 8)。
- 生成代码:`lact_qwen/synth.py` 的 `generate_dialogue`(第 125 行),命令行入口 `scripts/make_synth.py`。

### 0.3 一次评测是怎么跑的

1. 一段对话、一个问题、一个答案拼成**一个序列,一次前向**。模型不是一轮一轮输入的。
2. 在这次前向内部,记忆分支按轮从前往后处理:对第 t 轮,**先用当前记忆读取,再把第 t 轮写入**。代码:`lact_qwen/fast_weight.py` 的 `segmented_lact`(第 212 行)。
3. 问题和答案那一段只读不写。
4. 判分:把正确答案的 token 喂进去,看模型在每一位上预测的最大概率 token 是否都等于正确答案。全对才算对。代码:`lact_qwen/dialog.py` 的 `score_rows`(第 108 行)。
5. 入口脚本:`scripts/eval_select.py`。

### 0.4 指标

| 指标 | 含义 |
|---|---|
| 窗口外准确率 | 只统计"事实距离问题超过 2048 个 token"的题(注意力看不到,只能靠记忆)的答对比例。表里不特别说明时,"准确率"就是指它,而且只看"只说过一次的事实"这类题。代码:`scripts/eval_select.py` 的 `distance_bucket`(第 74 行) |
| 更正类准确率 | 只统计被更正过的事实,问的是最新值 |
| 答成旧值的比例 | 更正类题里,模型给旧值的概率比给新值高的比例 |
| 答案对数概率 | 正确答案每一位的对数概率之和,越接近 0 越好。比准确率灵敏,能看出"差一点答对" |
| 事实所在轮被写入 | 例如 `400/400 rows`:400 次(问题 × 候选)里,事实所在的那一轮有多少次被选进去写入了 |

### 0.5 题量和噪声

| 对话段数 | 32 轮的题数 | 64 轮的题数 | 准确率的大致误差(一个标准误) |
|---|---|---|---|
| 40 段 | 135 | 147 | ±4 个百分点 |
| 100 段 | 333 | 约 360 | ±2.7 个百分点 |

**两组结果相差小于约两个标准误(40 段时约 8 个点,100 段时约 5 个点),不能说有差别。**

## 1. 术语(表格里每一行的名字)

### 1.1 选择"写哪些轮"

| 术语 | 做法 | 代码 | 能否逐轮推理 |
|---|---|---|---|
| 全部写入 | 每一轮都写 | `--select none` | 能 |
| 选 K 轮 | 只有 K 轮在 28 层里都执行写入;其余轮照常前向、照常读记忆,但跳过写入 | `eval_select.py` 第 270 行起;开关传到 `memory_branch.py` `_segments`(第 322 行) | 取决于打分和怎么选 |
| 注意力打分 | 每一轮单独做:把"这一轮 + 问题"输入冻结底座(不带记忆),问题 token 放在这一轮 token 上的注意力总量(对头、问题 token、第 9–27 层取平均,对这一轮的 token 求和) | `--select turn_attn`;钩子第 187 行,打分第 365 行 | 打分能 |
| 内积打分(全文版) | 先把**整段对话全部写入**跑一遍,问题接在最后;取某一层问题 token 的读取向量和每个历史 token 的 key 的余弦相似度;每轮取最高 5 个 token 的平均 | `--select turn_qk --qk-source full`;第 312 行 | **不能**(偷看了后面所有轮) |
| 内积打分(逐轮版) | 每一轮单独做:输入"这一轮 + 问题",记忆为空、不写入;同样的相似度 | `--select turn_qk --qk-source turn`;第 283 行 | 能 |
| 上界 | 用标注:事实所在轮一定入选 | `--select turn_oracle`;第 350 行 | 不能(用了答案位置) |
| 随机 | 随机选 K 轮,对照用 | `--select turn_random`;第 352 行 | 能 |
| 前 K 名(离线) | 把全部轮的分数排序,取最高 K 轮 | `--turn-k K` | **不能**(要等所有轮到齐才能排序) |
| 门槛(逐轮) | 每轮到来时,分数超过固定门槛就写。门槛在开发集上定 | `--write-thresh`;第 368 行 | 能 |
| 内积用哪一层 | `--turn-layer 19`:用第 19 层的分数决定所有层写哪些轮。19 是在测试数据上挑出来的 | | 挑层用了标注 |
| 每层各自选轮 | 每一层用**自己那一层**的内积分数,选自己写哪 K 轮 | `--per-layer own`;第 379 行;`memory_branch.py` 第 329 行 | 用全文版时不能 |
| 有把握的层才选 | 一层里最高分比平均分高出 Z 个标准差才做选择,否则这一层全部写入 | `--per-layer confident --confident-z Z` | 同上 |

### 1.2 选择"每轮里写哪些 token"

| 术语 | 做法 | 代码 |
|---|---|---|
| 每层选 key | 被写入的轮里,每一层只写分数最高的一部分 token(10% 或 25%),其余 token 在这一层的写入强度设为 0。分数是本层的内积,先在相邻 7 个 token 内取最大值(SnapKV) | `--key-select layer --key-frac F`;`eval_select.py` 第 396 行;`memory_branch.py` 第 478 行 |
| 随机选 key | 同上,但随机选同样比例的 token(对照) | `--key-select random` |

### 1.3 保护已写入的内容

| 术语 | 做法 | 代码 |
|---|---|---|
| 排练(Robins) | 写每一轮之前,用一批"探针"向量去读当前记忆,记下读出值;写这一轮时,把"探针 → 旧读出值"和新内容放进同一次更新 | `--replay pseudo`;`replay.py` `_pseudo_pairs`(第 132 行) |
| 排练强度 | 探针那部分在更新里的权重(1、5、20) | `--replay-lr-scale` |
| 探针:问题单独 | 写入任何历史之前,问题单独前向一次得到的读取向量 | `--probe-src query`(不加 `--probe-ctx`)。能逐轮 |
| 探针:问题在上下文 | 来自一次整段对话全部写入后的前向 | `--probe-ctx`;第 423 行。**不能逐轮** |
| key 库 | 每写完一轮,把这一轮里分数最高的若干个 token 的 key 存进库(只存 key) | `--probe-src bank`;`replay.py` `observe`(第 246 行) |
| 每轮入库几个 | | `--replay-keep 8 / 16 / 32` |
| 入库依据 | `lr` = 模型学出的写入强度(和问题无关);`relevance` = 问题对 token 的注意力;`layer_qk` = 本层内积 | `--bank-score` |
| 受保护写入 | 写新的一轮时,把这次更新里"会改变库中 key 读出值"的部分去掉;库中 key 的读出值严格不变 | `--protect`;`replay.py` `project`(第 215 行);调用在 `fast_weight.py` 第 277 行 |
| 先擦后写 | 写入目标从 v 改成 v − a·(这个 key 当前已读出的值),同一个 key 再写一次会把旧值推向新值 | `--delta-erase a`;`fast_weight.py` 第 253 行 |

## 3. 目前可以说的和不能说的

能说的:
- 在这个合成任务上,跳过无关轮次的写入能让窗口外召回明显提高(E2)。但除"注意力打分"本身之外,E2 的选法都偷看了全文,逐轮版本(E10)还没有结果。
- 只写一轮里的一部分 token 会让这个模型的记忆失效(E9)。
- 用记忆分支自己的内积来选,依赖具体的一次训练和层(E3、E8)。

不能说的:
- Replay(排练、受保护写入)有效。唯一像样的提升(E5 最后一行)用的探针偷看了全文,E6 在验证。
- 这些结论在真实多轮对话上成立。数据是合成的,轮与轮之间没有关系。
