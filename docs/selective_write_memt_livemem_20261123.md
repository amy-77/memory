# 推理时选择性写入在 MemT-Qwen3-4B 和 LiveMem-RL 上的验证(LoCoMo)

2026-11-23。对应实验手册 E15(MemT)以及 LiveMem 的对齐实验。所有结果都**只改推理,不做任何训练**。

## 术语(先读)

| 词 | 含义 |
|---|---|
| 会话 | LoCoMo 一段对话由 19–35 次聊天组成,每次聊天叫一个会话(session),约 690 token,开头有日期 |
| 块 | 把输入从末尾往前按 2048 token 切开,每段叫一块。一块约等于 3 个会话 |
| 最后一块 | 装着问题和紧挨着的约 1.9K token 历史的那一块。注意力只看这一块 |
| 候选块 | 最后一块之前的所有块(平均每题 9.8 块)。注意力看不到它们,只能决定是否把它们写进记忆 |
| 写入 | 把一块交给记忆模块处理,更新记忆状态。不写的块整块跳过 |
| 答案位置标注 | LoCoMo 数据集为每道题标了"答案出自哪几句对话"(字段 `evidence`,例如 `D2:8` 表示第 2 个会话的第 8 句)。这是人工标的正确答案位置,**实际系统在推理时拿不到** |
| 含答案的会话 | 包含上述标注句子的会话,大多数题只有 1 个 |
| 含答案的块 | 和含答案的会话有重叠的候选块 |
| Oracle(上界) | 用了答案位置标注的设置。它告诉我们"如果挑得完全对,最多能好到什么程度",本身不是可用的方法 |
| 窗口外的题 | 最后一个含答案的会话结束的位置,距离问题至少 2048 token,也就是答案全在注意力看不到的地方。共 1298 题,下面的结果只统计这些题 |

## 0. 一句话结论

- **MemT-Qwen3-4B 上,选择性写入有效。** 如果挑块完全正确(Oracle:用答案位置标注,只写含答案的块),比随机挑同样多的块多答对 156 题(608 对 452,共 1298 题)。不用标注、按问题对历史的注意力挑块(S),比随机多答对 58 题、比全部写入多 63 题。
- **LiveMem-RL 上,写什么、写多少都没有区别。** 全部写入、Oracle 只写含答案的块、随机写入分别答对 423、419、414 题。原因是它的记忆遗忘很快:再经过 2048 个 token,早先写进去的状态只剩约 3%;MemT 还剩约 54%。
- **选择性写入起作用的前提,是记忆能把写进去的内容保留到读的时候。**

## 2. 两个模型

### 2.1 总览

| | MemT-Qwen3-4B(我们自己训的) | LiveMem-RL(官方发布) |
|---|---|---|
| 底座 | Qwen3-4B,全部冻结 | Qwen3-4B-Instruct-2507。模型卡说明 RL 阶段主干冻结、只更新记忆分支;SFT 阶段主干是否训练,模型卡没说 |
| 记忆的形式 | 每层一个矩阵状态(门控 delta 规则),36 层 × 32 头 × 128 维 | 每层一个 GDN2(Gated DeltaNet 2)循环状态,36 层 × 32 头 × 128 维 |
| 记忆的 q/k/v | 独立投影,初始化时拷贝注意力的 q/k/v 权重;L2 归一化,不加 RoPE | 独立投影,带短卷积 |
| 三个存储门 | 擦除 β、写入 ω、遗忘 λ,都由当前 token 算出;每 token 衰减上限 0.03;遗忘门初始化为半衰期 2K–32K token | 衰减 g、擦除 b、写入 w,由当前 token 算出,没有衰减上限 |
| 输出怎么接入 | 加在冻结的注意力 `o_proj` **输入**上,不经过记忆自己的投影 | 侧支经过**自己的** `o_proj` 后,加在注意力输出上:`o_main + o_side` |
| 读写时机 | 按块:块内 token 读"本块之前"的状态,读完才写入本块 | 逐 token 递推,记忆扫过每个 token(包括注意力窗口里的),论文称为 design X |
| 训练时的注意力 | 只看当前 2048 的块,更早的内容只能靠记忆 | 窗口 32K(短数据集用 8K) |
| 训练 | h20-1 上训练:LDC 通用长文本,只用交叉熵,2160 步(约 23 亿 token)。用的是 LaCT 的优化器配方,不是论文的 | 官方 SFT + GRPO |
| 这次评测用的权重 | `/mnt/airs-business/memory/memt4b_20261120/step_2160` | 官方 `chen-l/LiveMem-RL`,**直接加载,没有训练** |

### 2.2 MemT-Qwen3-4B 的说明

- 它是"MemT 式记忆在 Qwen3-4B 上的自实现",**不是论文的完整复现**。记忆模块的公式(写入、三个门、读出、输出门、接入位置)和论文一致;差别在底座、记忆层数(论文 Nano 每 4 层一个,我们全部 36 层)、门的低秩维度(256 对 128)、训练配方和数据量(论文第一阶段 200 亿 token,另有 140 亿 token 的记忆任务蒸馏;我们只有约 23 亿 token 交叉熵,没有第二阶段)。逐项对比见 `memt/README.md`。
- 一层里的数据流:`normed = input_layernorm(x)` 同时送进注意力和记忆;记忆读出 `q·S/√128`,经过每头 RMSNorm 和输出门 `2·tanh(SiLU(g)/2)`,再和注意力每个头的输出相加,进入冻结的 `o_proj`。

### 2.3 LiveMem-RL:只改推理,怎么改的

- **权重**:官方 `chen-l/LiveMem-RL`(`model.safetensors`,12.7GB),用它自带的 PyTorch 代码(`modeling_livemem.py`,`trust_remote_code`)按 bf16 加载。**没有做任何训练。**
- **改的只有推理流程**:把它放进和 MemT 完全相同的逐块流程里(见第 3 节),也就是注意力只看当前 2048 的块,记忆状态逐块传递,不写的块整块跳过。
- **为什么不用它自带的 vLLM 服务**:那个服务的窗口只能设 8192 或 32768,而且固定保留开头 1088 个 token 给注意力,和 MemT 对不齐。
- **之前的验证**:同一份权重在 9-5 上用它自带的服务复现过论文的 LongMemEval 数字(带记忆 0.298,论文 0.302;截断 0.304,论文 0.294),说明权重和环境没问题。

## 3. 数据和评测流程(两个模型相同)

**数据:LoCoMo。**
- 10 段长对话,每段是两个人几个月里的 19–35 次聊天(会话),每个会话约 690 token,整段 1.3–2.4 万 token。
- 去掉第 5 类(对抗题,没有答案),共 1536 道题。每道题都在整段对话结束后提问,输入是"这段对话的全部历史 + 问题"。
- **"窗口外"的题**:最后一个含答案的会话结束的位置,距离历史末尾至少 2048 token,即答案全在注意力看不到的地方。共 **1298 题**,下面的结果只统计这些题。按类别:单跳 721、多跳 224、时间 275、开放 78。
- 数据文件:由 LiveMem 处理过的 LoCoMo 转换而来(`livemem_patch/locomo_convert.py`),得到 `data/locomo2_g4.jsonl`(387 行,每行最多 4 道题,带含答案的会话编号)。

**切块。** 把"历史 + 问题 + 预留 64 token"从末尾往前按 2048 切块:
- **最后一块**:问题加上紧挨着的约 1.9K token 历史。注意力只看这一块,不保留开头的 token。
- **前面的块**:平均每题约 9.8 块,注意力看不到,只能通过记忆读到。
- 例子:第一段对话约 1.66 万 token,切成 9 块,最后 1 块给注意力,前 8 块是候选写入块。

**写入。** 被选中的块按时间顺序逐块写入记忆;没被选中的块**整块跳过**,不写、不擦,也不让记忆衰减。
- MemT:最后一块只读不写。它的块内 token 本来就只读"本块之前"的状态,所以写不写都不影响答案。
- LiveMem:最后一块和生成的 token 照常写入,这是它原本的逐 token 工作方式。

**生成。**
- MemT:纯文本续写,格式为 `[Turn i]` 加会话正文,然后 `Question: …\nAnswer:`,贪心解码最多 24 token,遇到换行停止。
- LiveMem:用它自己的对话格式,系统提示加上"会话 + LoCoMo 指令 + 问题 + 要求写成 `Answer: …`",贪心解码最多 48 token,从中取出 `Answer:` 后面的部分。

**判对错。**
- 裁判模型 Qwen3.6-35B-A3B(vLLM,温度 0)只看问题、标准答案和模型的答案,判 CORRECT 或 WRONG。标准比较宽松:同一事实、换一种说法也算对,比如 "8 May" 对 "7 May 2023"。这是 Mem0 等论文在 LoCoMo 上的通用做法。
- 同一个"问题 + 标准答案 + 模型答案"的组合只判一次,判定结果存成缓存,各行复用。
- 两次独立裁判之间,每行会有几题翻转,总数最多差 7 题。

## 4. 对比设置的含义(先读这一节)

| 行 | 名称 | 注意力看到什么 | 记忆里写了什么 | 用了答案位置标注吗 | 写入块数 |
|---|---|---|---|---|---|
| **A** | 完整注意力 + 完整上下文 | 整段历史 + 问题 | 不用记忆。MemT 用原版 Qwen3-4B;LiveMem 把记忆输出置零 | 否 | — |
| **B** | 完整上下文 + 本地窗口 | 只有最后一块(约 2K) | 不用记忆(做法同 A) | 否 | 0 |
| **C** | 全部写入 | 最后一块 | 本对话前面所有块,按顺序 | 否 | 全部(约 9.8) |
| **W** | 写入另一段对话 | 最后一块 | **另一段** LoCoMo 对话(数据里的下一段)的同样多块 | 否 | 同 C |
| **G** | 随机挑块 | 最后一块 | 随机挑的块,块数和 F 相同(= 这道题含答案的块数) | 只有块数用了 | 同 F |
| **S** | 按问题注意力挑块 | 最后一块 | 问题对历史注意力最高的块,块数和 F 相同 | 只有块数用了 | 同 F |
| **F** | Oracle:只写含答案的块 | 最后一块 | 含答案的块(由标注决定) | 是(上界,实际拿不到) | 平均 1.6 块(窗口外的题 1.7 块) |

补充说明:

- **"本对话"**指这道题所属的那一整段 LoCoMo 对话。
- **W 的作用**:如果记忆只是让模型熟悉了"LoCoMo 的对话长什么样",写别的对话也会有同样的提升。所以 **C − W 才是"记住了本对话内容"带来的部分**。
- **G 的作用**:和 F 写同样多的块,只是随机挑。F 比 G 好,说明好处来自"写对了内容",而不是"写得少"。
- **S 的打分**:用冻结的 Qwen3-4B 对"历史 + 问题"做一次完整注意力。每层每个头,把每个问题 token 的 query 和所有历史 key(加 RoPE 之后)做 softmax,得到注意力;对所有层、所有头、所有问题 token 加总,得到每个历史 token 的分数,开头 4 个 token 排除。一块的分数是块内 token 分数之和。这是 SnapKV 的思路,属于"先看到问题再写入"的设置,不是逐轮推理。
- **F 写多少**:写入的块占全部候选块的 16.5%(1536 题合计 2485 / 15033 块)。1536 题里有 1207 题只有 1 个含答案的会话;一块约等于 3 个会话,所以写含答案的块时会把相邻会话也一起写进去。只算含答案的会话本身,约占历史的 5%。
- **注意**:G 和 S 的块数等于这道题含答案的块数,所以这两行的"写多少"也间接用到了标注。完全不看标注、固定块数的版本见 5.4 和第 7 节。

## 5. 结果

### 5.1 MemT-Qwen3-4B(窗口外 1298 题,答对数)

| 行 | 含义 | 答对 | 单跳 /721 | 多跳 /224 | 时间 /275 | 开放 /78 |
|---|---|---|---|---|---|---|
| A | 完整注意力 + 完整上下文 | **999**(77.0%) | 629 | 192 | 133 | 45 |
| B | 只看最后一块,不用记忆 | 337(26.0%) | 221 | 68 | 18 | 30 |
| W | 写入另一段对话 | 387(29.8%) | 255 | 79 | 21 | 32 |
| C | 全部写入 | 447(34.4%) | 278 | 98 | 34 | 37 |
| G | 随机写入同样多的块 | 452(34.8%) | 278 | 100 | 37 | 37 |
| **S** | 问题注意力选同样多的块 | **510(39.3%)** | 310 | 100 | 58 | 42 |
| F | Oracle:只写含答案的块(上界) | 608(46.8%) | 361 | 131 | 73 | 43 |

逐题对比,只数两行中只有一方答对的题:

| 对比 | 只有前者对 | 只有后者对 | 说明 |
|---|---|---|---|
| C 对 B | 205 | 95 | 记忆有用 |
| C 对 W | 150 | 90 | 记忆存住了本对话的一部分内容 |
| F 对 G | 221 | 65 | 写的块数相同,写对内容能多答对很多题 |
| S 对 G | 144 | 86 | 不用标注的打分比随机挑得准 |
| S 对 C | 158 | 95 | 只写 16.5% 的块,反而比全部写入好 |
| S 对 F | 74 | 172 | 离上界还有距离 |
| A 对 C | 604 | 52 | 记忆离"看全文"还差得很远 |

写入的块里含答案的比例(三行写入的块数相同):G 24.3%,S 38.8%,F 100%。S 拿到了从随机到上界之间约 37% 的提升(58 / 156)。

另外两个答案对数概率上的检查:
- 挂着记忆但一块都不写(D),和不挂记忆(B)几乎一样(8 道题的冒烟测试,平均差 −0.03),说明空记忆基本不改变模型。
- 对数概率比 B 好的题的比例:C、G 为 97%,F 为 98%;W 为 95%。

### 5.2 LiveMem-RL(同样的设置,窗口外 1298 题)

| 行 | 含义 | 答对 | 单跳 | 多跳 | 时间 | 开放 |
|---|---|---|---|---|---|---|
| A | 完整注意力 + 完整上下文,记忆输出置零 | 554(42.7%) | 338 | 85 | 97 | 34 |
| B | 只看最后一块,记忆输出置零 | 115(8.9%) | 51 | 40 | 4 | 20 |
| C | 全部写入 | 423(32.6%) | 271 | 88 | 23 | 41 |
| F | Oracle:只写含答案的块 | 419 | 266 | 89 | 23 | 41 |
| G | 随机写入同样多的块 | 414 | 267 | 86 | 20 | 41 |

逐题对比:F 对 G 是 11 对 6,F 对 C 是 6 对 10,写什么都一样。C 对 B 是 341 对 33。

**A 和 B 不是公平的基线。** LiveMem 训练时记忆一直开着,把记忆输出置零后模型脱离了训练状态,常常回答"对话里没提到"(冒烟测试里 B 有一半的题这样回答)。所以 C 比 B 多出的 300 多题,不是来自早先块的内容(见 5.3),而是来自模型恢复了正常工作。公平的"不用早先内容"基线应该是"记忆开着、前面的块都不写",这一行还没跑。

**和论文对照。** 论文表 1(LoCoMo 用 8K 窗口、全部题目、采样解码):Qwen3-4B 0.255,LiveMem-SFT 0.295,LiveMem-RL 0.314;论文表 2 显示 LiveMem-RL 截断 0.299、带记忆 0.314,记忆只多 1.5 个点。我们的 C(2K 窗口、只算窗口外的题)是 32.6%,和论文同一量级。

### 5.3 为什么两者差这么多:遗忘速度

用同一道题测量(`diag_memt.py`、`diag_lm.py`):

| 指标 | MemT-Qwen3-4B | LiveMem-RL |
|---|---|---|
| 再写入一个 2048 块之后,早先的状态还剩多少(各层平均) | **54%**(浅层 30–50%) | **3%**(浅层 0.2–1.6%) |
| 早先的块对答案分布的影响(KL) | 0.028(对比只保留最后写入的那块);0.115(对比空记忆) | 6×10⁻⁹(最后一块照常写入);0.018(最后一块只读) |

- LiveMem 读到问题时,早先写入的内容已经衰减没了。它的记忆实际上只记得最近一两千 token,而这些注意力本来就看得见,所以写什么都一样。可能的原因:训练时注意力窗口有 8K–32K,记忆不需要把信息带到窗口外,于是学成了短程的辅助通路。
- MemT 训练时注意力只看 2048 的块,更早的内容只能靠记忆,所以学会了记得更久。但它每写一块也只保留约 54%,写满约 10 块时,早期写入的内容只剩约 1%。**MemT 上选择性写入有效,很大程度上是因为减少了含答案的内容被后续写入冲掉的次数。**

### 5.4 不用标注的挑块策略:挑得准不准(只打分,不生成)

**测什么。** 每道窗口外的题平均有 9.8 个候选块,其中含答案的块平均 1.71 个。每种策略给候选块打分,**每题固定挑 K 块,完全不看标注**,看挑中了多少含答案的块:
- 召回 R@K = 挑中的含答案的块 / 全部含答案的块;
- hit@K = 至少挑中一个含答案的块的题所占比例。

10 段对话中,前 3 段(324 题)用来选层和块内聚合方式,后 7 段(974 题)只用来报告。下表是后 7 段的数字。

| 策略 | 要先知道问题吗 | R@1 | R@2 | R@3 | hit@2 |
|---|---|---|---|---|---|
| 随机 | 否 | 0.100 | 0.199 | 0.297 | 0.312 |
| 最近优先(离问题近的块先写) | 否 | 0.054 | 0.170 | 0.255 | 0.239 |
| 意外度(记忆模型读这一块时的平均预测损失) | 否 | 0.101 | 0.184 | 0.266 | 0.299 |
| 问题注意力,全部问题 token、全部层、块内求和(就是 S 的打分) | 是 | 0.185 | 0.334 | 0.460 | 0.528 |
| 问题注意力,全部问题 token、9–17 层、块内取最大 | 是 | 0.321 | 0.482 | 0.589 | 0.759 |
| **问题注意力,只用问题的内容词、9–17 层、块内取最大** | 是 | **0.433** | **0.589** | **0.681** | **0.879** |
| BM25(问题和块文本的词匹配) | 是 | 0.419 | 0.565 | 0.646 | 0.855 |
| 记忆自己的 q·k,全部问题 token,每个 query 取块内最匹配的 1 个 key | 是 | 0.181 | 0.343 | 0.475 | 0.526 |
| 记忆自己的 q·k,只用内容词,每个 query 取块内最匹配的 1 个 key | 是 | 0.272 | 0.422 | 0.559 | 0.642 |

**两个改进:**
- **只用问题的内容词当 query。** 去掉 LoCoMo 的模板("Question:""Use DATE of CONVERSATION to answer with an approximate date.""Answer:")和停用词;例如 "When did Caroline go to the LGBTQ support group?" 只剩 Caroline、go、LGBTQ、support、group。这和 BM25 的处理一致。注意力打分的 R@2 从 0.482 升到 **0.589,超过了 BM25**;记忆 q·k 从 0.343 升到 0.422。模板词的 query 会去匹配每个会话都有的日期行之类的内容,把分数搅浑。
- **层和块内聚合方式。** 注意力用 9–17 层、块内取最大最好;"全部层、块内求和"(原来的 S)最差。层组和聚合方式都是在前 3 段对话上选的。
- **不知道问题时挑不出来。** 最近优先、意外度都和随机差不多,甚至更差。

**记忆 q·k 的汇总方式**(都只用内容词,9–17 层,测试集 R@2):

| 每个 query 在块内取几个 key | 直接平均 | 在块之间标准化后投票 |
|---|---|---|
| 1 个(最大值) | **0.422** | 0.347 |
| 4 个 | — | 0.350 |
| 16 个 | 0.374 | 0.321 |
| 64 个 | — | 0.294 |
| 100 个 | 0.299 | 0.287 |
| 全局前 100(每个 query 在整段历史里取前 100 个 key,按落在哪块计票,最接近 SnapKV) | 0.328 | |

**每个 query 取的 key 越多,效果越差;在块之间标准化也没有帮助。** 原因是含答案的块里真正匹配的通常只有几个 token(比如人名、关键事件词),而每一块里都有大量"还算相似"的 token。取得越多,这些普通 token 越多,把少数关键匹配淹没了。记忆 q·k 最好的版本(0.422)仍然明显不如注意力打分(0.589),说明这个只训了交叉熵的记忆,它自己的寻址方式还不够好,这和它的写入门不会挑是同一个现象。

- 代码:`score_strategies.py`、`score_strategies2.py`(打分,后者是只用内容词和多种 key 汇总方式的版本)、`analyze_strategies.py`、`analyze2.py`(召回率),结果在 h20-1 `out/strat/`、`out/strat2/`。

### 5.5 MemT 自己的门会不会挑

在 163 道窗口外的题上,按 C 的方式(全部写入)读完历史,记下每个 token 每一层的门值(在各个头和通道上取平均),看它能不能区分"含答案的会话里的 token"和其他 token。AUC 为 0.5 表示没有区分能力。

| 打分 | token 级 AUC |
|---|---|
| 写入门 ω | 0.508(各层 0.50–0.52) |
| 擦除门 √β | 0.509 |
| 写入强度 √β·ω | 0.511 |
| 保留(遗忘门取负) | 0.503 |
| 问题注意力探针(全部层求和) | 0.595 |

MemT 自己的门完全不会挑,这和"全部写入 ≈ 随机挑块"(447 对 452)一致。这个模型只训了交叉熵,门没有学会区分重要内容。要让"问题未知时也能挑",需要训练门,比如拿 BM25 或注意力打分当老师。代码:`gate_auc.py`,结果在 h20-1 `out/gate/`。

## 6. 局限和需要注意的地方

1. G 和 S 的写入块数等于含答案的块数,间接用到了标注。固定块数的版本见 5.4。
2. 每个设置只跑了一次(贪心解码,结果是确定的);裁判之间的波动在 7 题以内。
3. MemT 不是论文的完整复现(见 2.2),论文里应写作"MemT-style memory, our re-implementation on Qwen3-4B"。
4. LiveMem 的 A 和 B 把记忆输出置零,不公平。"记忆开着、前面的块不写",以及"完整注意力 + 记忆开着"这两行待补。
5. 只在 LoCoMo 一个数据集上测过。
