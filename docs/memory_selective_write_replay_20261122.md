# 记忆的选择性写入与 Replay:方案、代码路径与实验结论

> 更新时间:2026-11-22 上午。本文记录到目前为止确定的方案、所有代码和脚本的位置,以及哪些结论已有实验支持、哪些还没有。

## 0. 一句话结论

- **已经有实验支持的**:在"会精确写入事实"的记忆上,把写入集中到被问的内容上能大幅提高窗口外召回;在此基础上加 Robins 式排练还能再提高几个百分点。从问题出发、用模型注意力给历史打分,能在真实对话(LongMemEval)里定位到含答案的内容。
- **已经被实验否定的**:用记忆分支自己的 query·key 内积来挑内容(两个模型上都接近随机);在官方 LiveMem 权重上只改推理(即使用标准答案挑写入内容,准确率也不变)。
- **正在验证的**:训练时就带选择性写入,记忆能不能真正存住证据(LiveMem 微调,进行中,尚无结果)。
- **还没有任何实验的**:线性记忆上的 key 库排练(闭式恢复)和三种淘汰策略。

## 1. 问题设定

冻结的大模型加一个外挂记忆分支。注意力只看最近一个窗口,窗口外的历史只能通过固定大小的记忆状态起作用。问题是:历史里约 95% 的内容与将来的问题无关,它们同样在写入记忆、冲淡证据。

目标:**有选择地写入**(只写重要内容),并**排练(replay)**已写入的重要内容,使它不被后续写入覆盖。

## 2. 写入策略

### 2.1 核心做法

给每个 token 一个写入系数,乘到记忆更新上:

| 记忆类型 | 系数作用在哪 | 取值 |
|---|---|---|
| LaCT 快权重(非线性 MLP,梯度更新) | 该 token 的写入学习率 | 可大于 1(加强)或小于 1 |
| LiveMem / MemT(线性状态矩阵,delta 规则) | 遗忘、擦除、写入三个门 | 0 到 1;0 表示该 token 不写、不擦、不让状态衰减 |

注意:在线性记忆上,擦除和写入必须用同一个系数(两者合起来是步长为 α 的 delta 规则);遗忘是否用同一个系数是可选的,待做拆分实验(只挡写入 / 只挡遗忘)。

### 2.2 打分信号(决定系数)

| 打分 | 做法 | 结论 |
|---|---|---|
| 记忆分支的 query·key 内积 | 问题的记忆 query 与 token 的记忆 key 的相似度 | **不可用**。0.6B 模型和 LiveMem 上都接近随机(LiveMem:前 10 会话召回 0.29,随机 0.21;token AUROC 0.49) |
| 注意力总量(SnapKV 式,推荐) | 问题接在每个 2048-token 块之后,取冻结注意力中问题落在该块上的注意力总量 | **可用**。LongMemEval-s 前 10 会话召回 0.90–0.92,token AUROC 0.88;中间层和靠后层最好 |
| BM25 / 稀有 token 精确匹配 | 只用 token 统计,不跑模型 | 可用作参照。前 10 会话召回 0.94–0.96;不是我们的贡献,且对换说法的问题无能为力 |
| 标准答案(上界) | 数据集标注的证据位置 | 只作天花板参照,不是方法 |

关键教训:注意力概率在每个块内部归一化,不能直接跨块比较。块级相关度要用"问题落在整块上的注意力总量",块内再用逐 token 的注意力挑具体 token。

### 2.3 系数的形式

- 软权重:段内 `min(上限, n·softmax(标准化分数/τ))`(Select-TTT 的形式,细到 token)。
- 硬选择:分数做邻域最大池化后取前 k%(SnapKV 的形式)。
- 只增强、不压低:命中的 token 及其后若干 token 加权,其余保持 1。
- 无关的段应保持原样写入,不要在每段内部强行归一化(否则无关段也被挑出"最重要的 token",干扰更大)。

## 3. Replay 策略

### 3.1 LaCT 记忆上:Robins 伪排练(已实现并测试)

每写一个新块:

1. 写入前:取一批探针向量 q̃,读出当前记忆的输出 ỹ = f_W(q̃)。
2. 写入时:把新块的 (k, v) 与 (q̃ → ỹ) 放进同一次更新。

- 探针不随机生成:用问题在各层的记忆 query(问题单独前向一次,所有块复用),或历史中按分数挑出的 key,或两者。
- 目标取"写入带来的增量" f_W(q̃) − f_W0(q̃)(与只输出增量的读出方式一致),也可取完整读出。
- 探针强度 = 每个探针的写入学习率相对当前块平均学习率的倍数。

### 3.2 线性记忆(LiveMem / MemT)上:key 库加闭式恢复(已设计,未实现)

- **探针库存 key,不存 value,也不存问题的 query**。库里是之前各块中被选中 token 的记忆 key;value 从记忆里现读。
- 每个块:写入前用库里的 key 读一次记忆,记下读出 Y_old;写入后做一次闭式修正
  `S ← S + Pᵀ (P Pᵀ + λI)⁻¹ (Y_old − P S)`
  使库内各 key 的读出回到写入前的值,正交方向(新内容)不受影响。
- 不能用问题的 query 当恢复对象:那会把刚写入的答案抹掉。问题的 query 只用于打分。
- 同键更新(如住址从北京改到上海):新块中被选中的 key 与库内旧 key 高度相似时,该旧 key 本轮不恢复并被替换。
- 容量:每个头的 key 是 128 维,库内最多 128 个独立方向才能精确恢复;被保护的方向同时不能再写新内容,所以实际应远小于 128(计划从 16、32 试起)。

### 3.3 库的淘汰策略(待比较)

1. 只按分数淘汰。
2. 分数 × 新颖度(新 key 在库张成空间外的残差),相似的合并。
3. 不设库,改存重要 key 的协方差矩阵做软保护(对应 Overleaf 里的 C 线;与 ROME / MEMIT / AlphaEdit / RLS 的数学相同)。

## 4. 实验结果

### 4.1 小模型(Qwen3-0.6B + LaCT 记忆,自造的合成对话任务)——已弃用,仅作机制验证

32 轮对话,窗口外的事实召回(100 段对话,完整训练的模型):

| 写入策略 | 不排练 | 加 Robins 排练(强度 5) |
|---|---|---|
| 全部写入(基线) | 0.426 | 0.444 |
| 输入层精确匹配 | 0.432 | 0.450 |
| 上界(写入集中到被问的事实) | 0.480 | **0.538** |
| 记忆 query·key 内积选择 | 0.126–0.222 | 更差 |

中间检查点(第 200 步,50 段对话)上趋势相同且幅度更大:基线 0.367,上界 0.746,上界加排练 0.811。

结论:写对内容是主要因素;Robins 排练在此基础上稳定加分;排练也稳定改善答案的对数概率。局限:任务是自造的,模型是自己训的,样本量小。

### 4.2 LiveMem 官方权重 + LongMemEval-s

复现(500 题,裁判模型 Qwen3.6-35B-A3B):

| 设置 | 复现 | 论文 |
|---|---|---|
| 带状态,32K 窗口 | 0.298 | 0.302 |
| 截断到 32K | 0.304 | 0.294 |
| 完整上下文 | 0.438 | — |

只改推理的选择性写入(前 133 题,几乎全是单会话类):

| 策略 | 准确率 |
|---|---|
| 全部写入 | 0.303 |
| 上界:只写含答案的会话 | 0.306 |
| BM25 前 10 / 前 5 | 0.296 / 0.296 |
| 随机 10 个会话 | 0.291 |

- 系数全为 1 时与基线逐题输出完全一致(132/132),改动本身可靠;系数全程生效(调试日志确认)。
- 结论:官方 LiveMem 的记忆即使只装证据也读不出答案。原因判断:它训练时每个 token 都写入,从未见过选择性写入,记忆也没有学会存具体事实。**所以必须改训练。**

### 4.3 进行中:LiveMem 训练时加选择性写入

- 起点:官方 LiveMem-SFT 权重;数据:它第二阶段的混合数据;120 步,每 40 步存一次。
- 有证据标注的样本(MuSiQue、2Wiki、LongMIT)以 0.8 的概率启用选择:证据段落系数 1,其余记忆段落随机保留 0–30%,其余为 0;问题和答案始终为 1。
- 评测用子集:LongMemEval-s 均衡 120 题(六种题型各 20),2Wiki / MuSiQue / HotpotQA 各 200 题;每个模型都用"全部写入"和"上界"两种推理方式。
- 状态:训练刚启动,**尚无结果**。

## 6. 已知风险与待办

1. 线性记忆上的 key 库排练尚未实现;"选择性写入与排练在线性记忆上是否等价"只有推导。
2. 写入和遗忘用同一个系数只是一种选择,需做"只挡写入 / 只挡遗忘"的拆分。
3. 注意力打分需要问题在写入时已知,且每块多算几十个 token;多问题、问题未知的场景未覆盖。
4. 小模型结果样本量小、任务自造,只能说明机制。
5. LiveMem 微调的对照组(不带选择,同样步数)尚未跑。
6. 子集评测 120 题的误差约正负 4 个百分点,只用于筛方案,选定后需跑全量。
